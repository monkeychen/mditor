# PRD-v0.2.0：对标 Typora 的真所见即所得内核

## 1. 背景与目标

**一句话**：把编辑器内核从「CodeMirror 装饰器」换成「Milkdown（ProseMirror）所见即所得 + CodeMirror 源码模式」，让 mditor 的核心写作手感达到 Typora 水准。

**v0.1.0 真机验证暴露的问题**（用户反馈，2026-10-26）：
1. 光标进入某行时整行退化为小号源码，排版剧烈跳变；
2. 表格、列表、引用、图片均未正确渲染；
3. 没有 Typora 式的「实时渲染 / 源码」双模式。

**根因**：CodeMirror 装饰器方案以纯文本行为模型，表格、列表等块结构只能逐一手写替换组件，上限是 Obsidian Live Preview，无法达到 Typora 体验。技术决策已同步更新至 `GEMINI.md` 第 4 节。

**对用户的价值**：打字时排版始终稳定；表格、列表、图片在排版中直接编辑；需要精确控制时 `⌘/` 一键切到纯源码。

**需求变更说明**：
- `F2`（CodeMirror 6 驱动的 Live Preview）`[已废弃@v0.2.0]`，由本版 F8–F10 取代。
- `F3`–`F7` 能力保留，本版须在新内核下回归通过（见 F17）。

---

## 2. 用户故事

- **US1**：As a 写作者，I want 输入标题、加粗、列表时排版尺寸始终不变，So that 我能保持连续的写作心流。
- **US2**：As a 写作者，I want 用 Markdown 语法快速输入（如键入 `## ` 自动变成二级标题），So that 我不用离开键盘去点工具栏。
- **US3**：As a 知识工作者，I want 直接在排版好的表格里编辑、用 Tab 跳格、用工具栏增删行列，So that 我不用手动对齐 `|---|` 字符。
- **US4**：As a 技术写作者，I want 按 `⌘/` 切到纯源码模式，So that 我能精确排查语法或批量修改。
- **US5**：As a 用户，I want 用 mditor 打开再保存我的 Markdown 文件后内容不被无故改写，So that 我的文件能和 Git、其他编辑器安全协作。
- **US6**：As a 长文写作者，I want 专注模式、打字机模式和侧边栏（文件树 + 大纲），So that 我能沉浸写作并快速在文档间导航。

## 3. 功能需求与验收标准

> 快捷键以 macOS 为准，Windows / Linux 将 `⌘` 替换为 `Ctrl`。

### F8：所见即所得编辑内核（实时渲染模式，默认）

- 基于 Milkdown（ProseMirror + remark，CommonMark + GFM）渲染并编辑文档。
- 光标位于某个行内格式（加粗、斜体、删除线、行内代码、链接）内部时，仅该元素两侧以淡色露出定界符，样式保持；光标离开后定界符隐藏。
- 光标位于标题内时，`#` 前缀以淡色显示在标题左侧，标题字号、字重、行高保持不变。

**AC**：
- **AC-8.1**：打开含 H1–H6、加粗、斜体、删除线、行内代码、链接的文档，默认以排版样式呈现，不显示任何 Markdown 定界符。
- **AC-8.2**：光标移入 / 移出 H1–H6 标题时，该行 `font-size` 与 `line-height` 计算值变化为 0（E2E 读取 computed style 断言）。
- **AC-8.3**：光标置于 `**粗体**` 内部时 DOM 中出现定界符元素且文字仍为 `font-weight ≥ 600`；光标移出后定界符元素隐藏。

### F9：Markdown 输入规则与编辑行为

| 输入 | 结果 |
|---|---|
| 行首 `# `～`###### ` | 转为 H1–H6 |
| `**文字**` / `*文字*` / `~~文字~~` / `` `文字` `` | 转为加粗 / 斜体 / 删除线 / 行内代码 |
| 行首 `- ` / `* ` / `+ ` | 无序列表 |
| 行首 `1. ` | 有序列表 |
| 行首 `- [ ] ` / `- [x] ` | 任务列表（复选框可点击） |
| 行首 `> ` | 引用块 |
| 行首 `---` + 回车 | 分割线 |
| 行首 ```` ```lang ```` + 回车 | 代码块（见 F12） |
| `\|列1\|列2\|` + 回车 | 2 列表格（见 F11） |

- 列表 / 引用中回车延续同级项；空项上回车退出；`Tab` / `⇧Tab` 增减列表缩进。
- 成对符号自动补全：`()`、`[]`、`{}`、`""`、`''`、`` ` ` ``；选中文字后输入成对符号则包裹选区。
- 格式快捷键：`⌘B` 加粗、`⌘I` 斜体、`⌘K` 插入链接、`⌘1`～`⌘6` 设为标题、`⌘0` 设为正文。

**AC**：
- **AC-9.1**：上表每一种输入在 E2E 中键入后，DOM 中生成对应节点（每行一条用例）。
- **AC-9.2**：在列表项末尾回车生成同级新项；在空列表项回车退出列表；`Tab` 使列表项嵌套层级 +1。
- **AC-9.3**：选中「abc」后输入 `(`，结果为「(abc)」。
- **AC-9.4**：`⌘B` / `⌘I` / `⌘1` 等快捷键对选区生效，源码模式下可见对应 Markdown 语法。

### F10：源码模式与双模式切换

- `⌘/` 或底部状态栏模式按钮，在「实时渲染」与「源码」之间切换。
- 源码模式使用 CodeMirror 6：等宽字体、Markdown 语法高亮、行号可选，不做任何隐藏或组件替换。
- 两种模式共享同一份 Markdown 文本；切换时光标映射到对应位置。

**AC**：
- **AC-10.1**：按 `⌘/` 两种模式互相切换，单次切换耗时 ≤ 200ms（E2E 计时，5 万字文档）。
- **AC-10.2**：源码模式下修改内容，切回实时渲染后修改正确呈现，反之亦然。
- **AC-10.3**：光标位于某段落第 N 个字符时切换模式，切换后光标落在同一段落同一文字附近（偏差 ≤ 1 个块）。
- **AC-10.4**：状态栏显示当前模式名称，点击可切换。

### F11：表格

- GFM 表格在实时渲染模式下以表格元素展示，单元格内可直接编辑。
- 光标在表格内时显示浮动工具栏：上 / 下插入行、左 / 右插入列、删除行、删除列、列对齐（左 / 中 / 右）、删除表格。
- `Tab` / `⇧Tab` 跳至下 / 上一个单元格；最后一格按 `Tab` 新增一行；`⌘↩` 在下方插入行。
- `⌥⌘T` 弹出行列数输入并插入表格。

**AC**：
- **AC-11.1**：打开含 GFM 表格的文档，渲染为 `<table>`，表头加粗，对齐方式与 `:---:` 语法一致。
- **AC-11.2**：在单元格中输入「xyz」，切到源码模式可见对应单元格内容为「xyz」且表格语法合法（可被 remark 重新解析为相同结构）。
- **AC-11.3**：`Tab` 顺序遍历全部单元格；最后一格 `Tab` 后表格行数 +1。
- **AC-11.4**：工具栏每个操作执行后，表格行列数 / 对齐方式与预期一致（每个操作一条用例）。

### F12：代码块

- 围栏代码块内嵌 CodeMirror 6 编辑器：语法高亮、等宽字体、`Tab` 缩进。
- 右上角语言选择（可输入过滤）与一键复制按钮。
- 光标在代码块首行按 `↑`、末行按 `↓` 可离开代码块。

**AC**：
- **AC-12.1**：```` ```js ```` 代码块渲染时关键字带高亮 class。
- **AC-12.2**：修改语言为 `python` 后，源码模式下围栏语言标识同步变为 `python`。
- **AC-12.3**：复制按钮将代码内容（不含围栏）写入剪贴板。
- **AC-12.4**：末行按 `↓` 光标进入代码块后方段落；若后方无段落则自动新建。

### F13：图片

- 支持三类来源：文档同级相对路径（`./assets/a.png`）、本地绝对路径、`http(s)` 网络图片。
- 光标移到图片上时，在图片上方露出 `![alt](path)` 源码供编辑，图片同步刷新。
- 加载失败显示占位卡片（文件名 + 「图片无法加载」）。
- 继承 F4：粘贴截图 / 拖入图片自动存入 `./assets/` 并插入相对路径。

**AC**：
- **AC-13.1**：三类来源的图片在 E2E 中均成功加载（`naturalWidth > 0`）。
- **AC-13.2**：路径无效时出现占位卡片，控制台无未捕获异常。
- **AC-13.3**：编辑图片源码中的路径后，图片按新路径刷新。
- **AC-13.4**：F4 原有用例（粘贴 / 拖拽落盘）在新内核下全部通过。

### F14：源文件保真

- 打开再保存（未编辑）时文件内容逐字节不变。
- 编辑某处后保存，未编辑的块逐字节不变。
- 无法逐字节保真的写法须在 spec 中明示，并在首次改写时提示用户。

**AC**：
- **AC-14.1**：建立保真测试语料库（≥ 30 个 `.md` 文件，覆盖 CommonMark / GFM 常见写法，含 `*` 与 `-` 列表、`__` 与 `**`、各种表格对齐、HTML 片段、Front Matter），「打开 → 不编辑 → 保存」逐字节一致率 100%。
- **AC-14.2**：在语料文件中修改一个段落后保存，`diff` 结果仅包含被修改的段落。
- **AC-14.3**：保真测试纳入 `npm run test:all`，任一失败即阻断合入。

### F15：侧边栏（文件树 + 大纲）

- `⇧⌘L` 显示 / 隐藏侧边栏；侧边栏顶部切换「文件」/「大纲」两个视图。
- 文件视图：展示当前文档所在文件夹的 Markdown 文件树，单击打开（复用 F1 标签页）。
- 大纲视图：继承 F5，展示 H1–H6 层级，点击跳转，高亮当前所在章节。

**AC**：
- **AC-15.1**：`⇧⌘L` 切换侧边栏可见性。
- **AC-15.2**：文件视图列出当前文件夹下全部 `.md` 文件（含子目录），单击后在新标签页打开。
- **AC-15.3**：大纲点击某标题后，该标题滚动至视口内且光标位于该标题。
- **AC-15.4**：滚动正文时，大纲中当前章节高亮随之变化。

### F16：专注模式、打字机模式、字数统计

- 专注模式（`F8`）：除光标所在块外，其余内容降低不透明度。
- 打字机模式（`F9`）：光标所在行始终保持在视口垂直居中。
- 状态栏显示字数（中文按字、英文按词）与预计阅读时长；选中文本时显示选区字数。

**AC**：
- **AC-16.1**：专注模式下非当前块 `opacity < 1`，当前块 `opacity = 1`。
- **AC-16.2**：打字机模式下连续输入 50 行，光标所在行中心与视口中心偏差 ≤ 1 行高。
- **AC-16.3**：对已知样本文本（中英混排）字数统计结果与预期值一致。

### F17：v0.1.0 能力回归

- F1 多标签页、F3 文件读写与自动保存、F4 图片落盘、F5 大纲、F6 查找替换、F7 导出 HTML / PDF 与微信复制，在新内核下全部可用。
- F6 查找替换基于新内核重写：实时渲染与源码模式下均可用。

**AC**：
- **AC-17.1**：v0.1.0 的 54 个自动化用例中，与 F1、F3–F7 相关的用例在新内核下全部通过（与已废弃 F2 绑定的用例改写为对应的 F8–F10 用例）。
- **AC-17.2**：查找替换在两种模式下均能正确计数、定位与替换。

### F18：性能基线

**AC**：
- **AC-18.1**：打开 5 万字中文文档至可编辑 ≤ 1.5s（E2E 计时，GitHub Actions macOS Runner）。
- **AC-18.2**：在 5 万字文档中连续输入 100 个字符，单键平均响应 ≤ 50ms。

## 5. 非目标（v0.2.0 不做）

1. 数学公式（KaTeX）、Mermaid 图表、脚注、`[TOC]` 目录、`==高亮==`、上下标 → v0.3.0；
2. 主题系统与自定义 CSS、Pandoc 导出 Word / ePub、图床上传、偏好设置面板 → v0.4.0；
3. 多人协同编辑、云同步、移动端；
4. 使用 Typora 的名称、图标、内置主题或任何代码（对标红线，见 `GEMINI.md` 第 1 节）。
