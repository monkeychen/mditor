# PRD-v0.5.1：系统原生 Help 菜单增强、关于面板与 TabBar 智能悬停提示

## 1. 背景与目标

在 mditor v0.5.0 顺利交付海量文档闪电检索、原生拖拽管理与出版级多格式导出后，应用已迈入成熟桌面工具阶段。

然而，在日常桌面操作与社区反馈中存在以下体验细节缺失：
1. **菜单栏信息盲区**：桌面系统顶栏菜单中缺少规范的 **Help（帮助）** 菜单项，用户无法直接在菜单中查看当前安装的版本号与核心语法指南；
2. **开源项目与作者连接断层**：缺少项目官方开源代码仓库（GitHub）链接与作者联系渠道，用户在遇到使用问题或需要贡献代码时难以快速触达；
3. **偏好设置关于面板缺失**：偏好设置模态框（`⌘,`）中仅有外观、编辑器、文件三项设置，缺少主流软件标配的「关于 (About)」展示卡片；
4. **多标签页信息辨识低效**：
   - 当打开位于不同目录的同名文档（如多个 `README.md`、`spec.md`）时，标签栏仅展示文件名，无法一眼确认文件的物理路径；
   - 当连续新建未保存草稿（`Untitled.md`）并在其中起草内容时，悬停在 Tab 上无法获知其正文主题，需频繁切换标签查验。

**v0.5.1 核心定位**：构建符合 macOS / Windows / Linux 桌面规范的**「系统原生 Help 菜单体系与偏好设置关于面板」**，同时提供符合 Typora / macOS 极致体验的**「TabBar 标签页悬停智能感知提示系统」**。

---

## 2. 用户故事

- **作为一名日常使用者**，当我点击系统顶部「Help」菜单或进入应用偏好设置时，我希望能一眼看清我正在使用的 mditor 具体版本号，并随时查阅 Markdown / Mermaid / 数学公式语法指南。
- **作为开源社区开发者**，当我想要阅读源码、提交 Issue 或 Star 支持时，我希望能直接从 Help 菜单或关于面板一键跳转至 GitHub 仓库页面。
- **作为多项目管理开发者/研究者**，当我在顶栏打开了来自不同工作目录的文档时，我希望能将鼠标悬停在 Tab 上立即看到该文件的完整磁盘绝对路径。
- **作为一名灵感记录创作者**，当我按 `⌘T` 新建了几个未保存的随手草稿并写下要点时，我希望能悬停在 Tab 上一眼看到该篇文档的标题（第一行文字），而无需逐个点击切换去查验内容。

## 3. 功能需求

### F38：系统原生 Help 菜单增强与偏好设置「关于」信息面板

- **AC-38.1 [系统原生 Help 菜单与核心指南条目]**：
  - 应用菜单中显式挂载规范的 **Help** 菜单（macOS 顶栏、Windows/Linux 原生菜单）；
  - 菜单聚焦实用写作辅助与高信噪比，不在顶层平铺罗列散落信息，包含以下核心条目：
    1. **Markdown 语法指南**：唤出 Markdown 基础与高级语法速查；
    2. **Mermaid 图表指南**：唤出流程图、时序图、类图、状态图等主流图表语法速查；
    3. **数学公式语法指南**：唤出 KaTeX / LaTeX 行内公式、独立公式块与常用符号速查；
    4. 分割线；
    5. **关于 mditor**：保留并呼出原生关于卡片（About Dialog），集中呈现版本号、GitHub 地址与作者信息。

- **AC-38.2 [交互式使用指南速查组件（Guide Modal）]**：
  - 支持从 Help 菜单各条目直接呼出并自动定位到对应选项卡（Markdown / Mermaid / 数学公式）；
  - 每个语法项包含语法名称、场景说明与可复制的代码片段；
  - 提供「一键复制代码」与「插入到当前文档光标处」动作；
  - 提供「在新标签页中打开完整文档」快捷按钮，自动将指南作为 Markdown 文档在编辑区打开供沉浸式学习体验。

- **AC-38.3 [内置偏好设置「关于」交互面板与安全外链]**：
  - 在偏好设置（`⌘,`）中常设「关于 (About)」选项卡，集中呈现关于卡片：
    - mditor 琥珀金精致 App Icon 徽章与产品标题；
    - 当前运行版本号标签（`v0.5.1`）；
    - 一句话产品定位标语；
    - 项目地址链接（带外链箭头图标，点击安全在浏览器打开）；
    - 作者姓名与邮箱联系按钮（带邮件图标，点击唤起系统邮件客户端）。
  - 主进程建立严格的外链协议白名单检查，拦截非 `https:` / `http:` / `mailto:` 协议，防御潜在注入风险。

- **AC-38.4 [系统原生关于面板与对话框对齐]**：
  - macOS 平台调用 `app.setAboutPanelOptions`，对齐系统自带「关于 mditor」原生面板信息；
  - 触发关于对话框时，弹出包含产品简介、版本号、GitHub 访问按钮与邮件联系按钮的原生弹窗。

### F39：TabBar 标签页悬停智能感知提示（Tab Tooltip & Unsaved Title Detection）

- **AC-39.1 [已保存文档路径悬停提示]**：
  - 针对已存在于本地磁盘的文档（即具有有效 `filePath` 的标签，无论当前内容是否修改处于 dirty 状态）；
  - 鼠标悬停在对应 Tab 区域时，Tooltip 提示显示该文档的完整绝对路径（如 `/Users/chenzhian/workspace/docs/spec.md`）。

- **AC-39.2 [未保存新建文档智能标题提取]**：
  - 针对尚未在磁盘保存过的新建文档（即 `filePath` 为 `null` 或未定义的临时草稿标签）；
  - 鼠标悬停在对应 Tab 区域时，系统智能提取文档正文的第一行有效文本作为标题展示；
  - 若第一行包含 Markdown 标题标记（如 `# 项目方案`、`## 核心架构设计`、`### 会议纪要`），自动剔除前导 `#` 与空格，返回纯净标题文本；
  - 若文档首部存在连续空行，自动跳过空行，提取首个非空白行的文本。

- **AC-39.3 [新建空白文档优雅回退]**：
  - 若新建文档正文内容为空，或仅包含换行符与空格，无法提取有效标题时；
  - Tooltip 提示优雅回退显示当前标签文件名（如 `Untitled.md`）。

- **AC-39.4 [全 Tab 交互区悬停触发]**：
  - Tooltip 挂载在 Tab 项的外层交互容器及文本节点上，确保用户鼠标悬停在标签项的任何可视位置均可平滑唤起提示；
  - 标签本身的显示文本仍然保持原样（`fileName`），不破坏多标签栏的横向紧凑布局与视觉一致性。

## 5. 非目标（v0.5.1 暂不包含）

1. 不修改 Tab 标签文字本身的截断与显示规则（标签主体依然显示文件名 `fileName`，避免长标题破坏标签栏紧凑排版）；
2. 不引入额外的浮动 DOM 弹层重渲染，采用原生可访问性标准 `title` 属性，兼顾极致性能与无障碍体验；
3. 不自动执行静默磁盘命名保存：悬停预览标题仅作为只读感知辅助，保存文档仍需用户主动调用 `⌘S` 触发对话框。
